# App Proxy 首版设计（已确认方向的实现记录）

SwiftUI macOS 14+ 应用，使用固定版本 sing-box 1.14.3（darwin arm64）TUN；无需 Apple 开发者账号。应用启动不启用网络，只有用户点击“启动网络接管”才请求 macOS 管理员授权。

## 模块与边界

- AppProxyKit：可序列化代理/应用规则、验证、应用路径匹配、Keychain、原子持久化、内核配置编译、运行状态与脱敏。
- AppProxy：SwiftUI 界面，管理 SOCKS5/HTTP CONNECT 上游和有顺序的应用规则；提供运行状态、日志、显式启动/停止。
- AppProxyHelper：单次授权会话的独立网络监督进程。输入仅为严格解析的代理与规则模型，自己生成内核配置；不接受任意命令、任意内核或任意配置。固定捆绑内核经 SHA-256 校验后复制到 root 私有目录运行。无常驻特权服务。
- tools/attribution：用该版本 sing-box 的 Darwin socket 查询实现验证两个真实可执行程序的 TCP/UDP 归属。
- scripts：固定摘要下载、构建 .app、普通集成测试与显式特权验收。

## 数据与规则

普通配置只记录用户名和密码是否已设置，密码按代理 UUID 保存至 Keychain。启动时密码仅进入 0700 会话目录下的 0600 临时请求；helper 读取后立即删除，再把含凭据的运行配置保留于 root 0700 临时目录；停止/失败后清理。禁止记录原始配置和认证字段。

应用选择读取 .app 的 CFBundleExecutable，并将包内可执行文件与锚定、转义后的包路径正则用于匹配，以覆盖内置 Helper/XPC。包外共享系统进程不能据此归为该应用，显示未知/独立进程，默认直连。规则按列表先后顺序；禁用规则不参与编译。删除被引用代理应拒绝。

## 网络策略

TUN 接收 IPv4/IPv6 流量，已匹配 TCP 分配到指定上游；内核出站绑定自动检测的原网络接口避免循环，内核自身规则直连。未匹配默认直连。已匹配 UDP 明确拒绝（包括 QUIC，使支持的客户端回退 TCP），不声称 UDP 代理已实现。DNS 明确直连：dns_mode disabled，不写系统 DNS；端口 53 的流量直连，因此不提供 DNS 隐私。共享 DNS 进程无法按应用分配。IPv6 TCP 配置进入相同规则，但在授权测试前不能标为实际验证。

进程未知默认直连是可用性策略，不是防泄漏保证。已识别且匹配的 TCP 上游故障必须报错，不能自动回退直连。Loopback、本地链路及系统路由优先级可能限制接管范围，需记录。

## 生命周期与恢复

UI：未启动→启动中→运行中→停止中→未启动；授权取消、配置错误、上游不可达、内核退出与恢复差异为具体失败原因。编辑配置仅在停止时允许。helper 监听 STOP 文件及 UI 心跳，UI 退出/崩溃则结束内核；异常内核退出同样清理。启动前/结束后只读记录路由及 DNS，比较并报告差异，不导入旧快照覆盖其他网络工具。关闭 utun 由系统清理该接口路由；DNS 从不主动更改。恢复核验不能仅依靠退出码。

管理员授权缺失时完成所有无特权验证及打包，并提供独立、显式的最终 TUN 验收命令。不得将未运行的 TUN 验收写为通过。

## 验证与交付

Swift 测试覆盖无效配置、凭据隔离、规则优先级/Helper/正则转义、持久化、运行状态和清理。固定二进制校验实际生成配置；loopback 本地 SOCKS5/HTTP CONNECT 上游提供真实 TCP 转发与故障证据；进程归属测试使用两个真实执行程序。构建可打开的 ad-hoc 签名 .app，附许可、源码位置、构建与验证说明。提交推送功能分支并提供 PR，明确授权验收未完成项。
